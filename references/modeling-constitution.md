# 数学建模宪法

本页定义 `cumcm-team-ai` 的最高层建模原则。工作流、DAG、模型目录、评分器与论文工具都服务于这些原则，不能反过来替代建模判断。

## 1. 忠于题目与官方口径

先建立 `problem contract`：题目要求什么输出、使用什么定义、单位和约束、哪些公式是题面契约。题目给出的定义优先原样采用；只有数学上等价的改写可以替代，并应说明等价关系。若数据不支持题目口径，必须显式记录差异、影响和补救，不能悄悄换定义。

## 2. 大道至简：复杂度必须挣得资格

默认从能完整回答问题的最简单 formulation 开始。参数越少越好，但每个保留参数都应有数学、物理、统计或业务含义。复杂模型只有在简单 baseline 的具体缺陷已经被数据、残差、边界条件或反例量化证明后才升级。

推荐顺序不是固定算法排名，而是：

`题目契约 → 数据/单位 → 结构扫描 → 简单 formulation → baseline → 诊断缺陷 → 必要时升级 → solver`

因此，solver/algorithm 是最后一层工具，不是第一层思考入口。

## 3. 结构优先，但不制造伪机理

优先利用已经存在的结构：守恒、几何、图/树结构、单调性、凸性、对称性、稀疏性、尺度分离、条件独立、可分性、边界与不变量。能解析、消元、降维、分解或粗到细时，不应无理由直接全域黑箱拟合或暴力搜索。

“机理优先”不等于“机器学习只能做配角”。当任务本质上是高维数据预测、可靠机理不足，ML 可以是主模型；但必须使用真实泛化评估、泄漏检查和必要的解释/消融。若只知道部分机理，优先考虑 grey-box：`known structure + learned residual/unknown term`。

## 4. 可解释、可验证、可追溯

论文中的关键公式、变量、参数和结论应能回到题面、数据或模型假设。关键结果至少有一种独立 sanity check：解析解、toy case、上下界、量纲、守恒、重算、外部基线、holdout/CV 或独立实现。

解释性不是装饰性 SHAP 图，而是能回答：为什么这个 formulation 合理、关键参数意味着什么、结论在哪些条件下成立、失败时会怎样。

## 5. 真实数据与诚实证据

不得用未标注的合成数据冒充题目数据。随机数可用于蒙特卡洛、随机重启、bootstrap、仿真或测试夹具，但必须说明用途、固定随机种子并与真实输入边界区分。

改善小就如实写小；方案退化就解释 trade-off；实验失败保留记录。不能挑选单个漂亮指标掩盖整体退化，也不能把“运行成功”写成“模型正确”。

## 6. 创新发生在结构与表示层，证据决定是否能宣称

创新协议以 `references/structural-innovation.md` 为准。优先寻找合理假设带来的降维、消元、重参数化、解耦、coarse-to-fine、剪枝、搜索空间压缩、grey-box 接口等。算法堆砌、冷门名称、超参数微调、A+B+C 拼接默认不算创新。

`innovation opportunity` 只是待检验假设；只有公平 baseline/proposed 对比、failure-oriented test 和风险 guard 均有证据后才成为 `verified innovation claim`。允许 0 个创新点。

## 7. 模型目录只是工具书

`references/model_catalog.md` 用于 formulation 已明确后补充候选 solver/model family，不是关键词到算法的路由器。不得采用“预测题→LSTM”“优化题→GA/PSO”“评价题→AHP/TOPSIS”的机械映射。

优先级固定为：

1. 当届官方规则与题面契约；
2. 本页建模宪法；
3. `structural-innovation.md`；
4. `production/modeling.md` 的竞赛建模经验；
5. `model_catalog.md` 按需查阅；
6. 经验页数、图数、公式数、配色等启发式建议。

低层经验不得覆盖高层数学事实或赛事规则。

## 8. 每个子问题的最小决策记录

在进入求解前至少回答：

- 题目真正要求的输出与口径是什么？
- 已知数据、单位、缺失和可能泄漏是什么？
- 有什么可利用结构，哪些明确为 `none`？
- 最简单可行 formulation 是什么？
- baseline 是什么，为什么公平？
- 哪个证据证明需要更复杂模型？若没有，就停在简单模型。
- solver 为什么适合这个 formulation？
- 如何验证关键结果和失败边界？

这份记录由 Stage 2/3 和 task DAG 消费，不要求额外新增一个阶段。
