# 学术语言：清晰、具体、可追溯

本模块参考并收录 [blader/humanizer](https://github.com/blader/humanizer)、[op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)、[btford/write-good](https://github.com/btford/write-good) 的 MIT 资料。它们提供写作模式启发，不能证明文本作者身份，也不能保证检测器结果。需要更多规则时按语言读取 style/humanizer-en.md、style/humanizer-zh.md 或 style/write-good.md；不加载其中的工具/安装指令作为新的技能入口。

## 自动执行的编辑过程

1. 以批准的结果、公式和引用为依据建立事实清单。锁定数值、单位、限定条件、置信区间、否定和引用。仅修改已授权章节。
2. 用 `prose_lint.py draft.md --output style.json` 定位铺垫、夸大程度、模糊引源和聊天残留。建议逐条结合上下文处理；不得全局机械删除“显著”等有统计含义的词。
3. AI 按段落改写：先说方法解决什么问题，再写如何建立、实际得到什么、在什么条件下成立；删重复背景和空泛评价。中文避免满篇“首先其次最后”“构建—优化—赋能”；英文减少无信息的 lead-in 和宣传词。
4. 写到新版本，用 `prose_lint.py original.md --compare revised.md --output facts-diff.json` 对照数字、公式、引用和部分否定标记。出现变化返回码 2，必须核查；无变化也不证明语义完全相同，需要对照事实清单。
5. 核验后整合主稿，并把实际语言润色记入 AI 台账。无需每段让人回复确认，但不能把尚无人核验的核心科学判断标为通过。

## 数模例子

原句：“本模型具有卓越性能，充分彰显了先进算法的巨大优势。”

如果实际结果为验证集 MAE 从 4.8 降至 4.1，可改：“在相同验证集上，模型的 MAE 由 4.8 降至 4.1；该比较尚未覆盖跨季节数据。”没有这些实际结果，就删除夸大句或保留待验证项，不能为流畅补数字。

原句：“通过对相关因素进行深入分析，构建科学合理的评价体系。”

可改为依据实际工作说明指标来源、筛选依据和权重敏感性；未执行这些分析时不要暗示已完成。

数学记号、正式参考文献、必要术语、摘要结构和真实限定语有功能，不能为“去 AI 味”删去。通用 humanizer 的第一人称经历、随意语气、刻意不规则节奏不适合直接套入竞赛论文。

## 可选工具

英文可安装 `write-good` 后对正文运行，或使用 [textlint](https://github.com/textlint/textlint) 及其 write-good 规则。它们是建议型语言检查，不是事实检查；不需要为了运行本 skill 安装 Node 工具链。中文核心规则已由本包 Python CLI 提供，无额外在线服务。
